# Building the firmware

The target is `NUCLEO_L432KC`. `mbed-os.lib` pins Mbed OS 6.17.0 to commit `17dc3dc2e6e2817a8bd3df62f38583319f0e4fed`.

Use a compatible Python environment with Mbed Tools, CMake 3.19 or newer, Ninja, and an Arm GNU toolchain available on PATH. The exact Arm compiler version has not yet been validated for this repository.

From the repository root:

```sh
mbed-tools deploy
mbed-tools compile -m NUCLEO_L432KC -t GCC_ARM
```

The `mbed-os/` dependency and generated `cmake_build/` tree are ignored by Git. Mbed CLI 2 normally writes the binary below `cmake_build/NUCLEO_L432KC/develop/GCC_ARM/`. Flash the binary generated by a successful target build to the board using ST-LINK, then open its virtual COM port at 115200 baud. The historical demonstration binary is not included.

Before relying on the firmware, check:

1. Sensor initialization succeeds with the documented wiring.
2. The stationary startup calibration produces no motion alarm in the chosen mounting orientation.
3. Correct, incorrect, held, bounced and overlapping button inputs behave as documented.
4. Temperature and motion alerts continue during the one-second password feedback window.
5. Disconnecting each sensor produces a fault alert; reconnect and reset before the next startup test.
6. The passive buzzer is audible and LED polarity matches the active-high outputs.

The native tests are separate from the ARM build. They use test doubles and do not need the Mbed dependency. See [tests/README.md](tests/README.md).
